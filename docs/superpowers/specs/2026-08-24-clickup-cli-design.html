1. Goal & shape

A Rust CLI exposing the ClickUp API (v2 + the v3 Docs/Chat endpoints) as composable noun-verb subcommands with strict JSON output, built for AI agents, with a bundled agent skill. It follows intacct-cli's architecture — the refined sibling — everywhere it applies, simplified where ClickUp's auth model allows.

  • In scope: every mainstream API family typed (tasks, lists, folders, spaces, comments, checklists, tags, custom fields, dependencies/links, attachments, time tracking, views, goals, docs, chat, users, groups, webhooks, templates, workspace info), a raw escape hatch, multi-account keyring auth, self-update, embedded skill, wiremock test suite, 3-OS CI + tag-driven releases.
  • Out of scope (reachable via raw): enterprise-only guests, audit logs, custom roles, privacy/access updates. No OAuth2 flow, no webhook listener (only webhook CRUD), no output formats other than JSON.

2. Auth, accounts, config

Personal API token only (pk_…). Tokens don't expire and are sent verbatim in the Authorization header. No token cache, no refresh, no TokenProvider indirection beyond a minimal trait for test injection; a 401 is a real auth failure → exit 3, never retried.

Bootstrap

clickup-cli account add work            # token from $CLICKUP_CLI_TOKEN or hidden prompt — never a flag
clickup-cli account test                # GET /v2/user → {"ok":true,"user":...,"workspace":...}
  • account add validates the token with GET /v2/user, fetches workspaces with GET /v2/team; a single workspace is stored automatically, multiple → pick interactively (TTY) or via --workspace-id.
  • First account added becomes default_account. Write ordering: config before keychain on add, config before keychain-delete on remove (partial failures stay re-runnable; regression-tested with a failing store, same as intacct-cli).
  • Verbs: add, list (never shows secrets), set-default, remove, test.

Resolution & globals

  • Alias: --account → $CLICKUP_ACCOUNT → default_account → usage error naming the exact remediation command.
  • --workspace <id> (global) overrides the configured workspace_id for team-scoped endpoints — fills intacct-cli's --entity slot.
  • --pretty (global) indents; JSON is otherwise unconditional and compact. No --json flag, no color (ColorChoice::Never), no logging framework.
  • Env: CLICKUP_ACCOUNT, CLICKUP_CLI_TOKEN (bootstrap only), CLICKUP_API_BASE (tests/mocks), CLICKUP_LIVE_ALIAS (live smoke), GITHUB_TOKEN (self-update), CLAUDE_CONFIG_DIR (skill install).

3. Command surface

Noun families with verb subcommands (#[derive(Subcommand)] enum XAction per family). Positionals for identity, kebab-case --long flags only, --data accepts inline JSON / @file / - (stdin), after_help carries copy-paste-correct examples on every subcommand.

4. Client & HTTP behavior

  • CuClient wraps reqwest (rustls, no default features): base https://api.clickup.com, override via CLICKUP_API_BASE and constructor injection (tests). Commands address /api/v2/… or /api/v3/workspaces/{id}/… explicitly.
  • One shared send_with_retry loop (JSON, multipart, and any binary paths): MAX_ATTEMPTS = 4, honor Retry-After on 429 (ClickUp: 100 req/min/token), exponential backoff 500ms·2^n on 5xx. 401 fails immediately with exit 3 — personal tokens can't be refreshed, so unlike the siblings there is no reauth-and-retry branch.
  • Error mapping: ClickUp bodies are {"err":"…","ECODE":"…"} → envelope {"kind":"api","message":err,"status":N,"ecode":"…"}; ecode omitted when absent (the supportId pattern from intacct-cli).
  • Pagination: listing endpoints are page-based (100/page, some return last_page). --page N for one page; --all merges into {items, count, hasMore} with the sibling safety rails — MAX_PAGES cap and a stop when a page contributes zero items; hasMore:true in merged output means partial data (documented in the skill).

5. Output contract

ExitkindMeaning
0—success; stdout is exactly one JSON value (compact; --pretty indents)
1apiClickUp rejected the call; envelope adds status, ecode?
2usagebad invocation — includes clap parse failures, folded in via handle_clap_error; only --help/--version print human text (stdout, exit 0)
3authtoken missing/invalid (401/403 auth-shaped)
4networktransport failure after retries

Errors are one JSON object on stderr. Prompts and notices go to stderr, never stdout. Success shapes pass the API body through untouched; synthesized shapes only where there's no body ({"deleted":true,…}, account/skill/update results).

6. Crate layout

src/
  main.rs            # 4 lines: exit(clickup_cli::cli::cli_main().await)
  lib.rs             # pub mod account, auth, cli, client, commands, config, context, error, output, secrets
  cli.rs             # entire clap tree + cli_main + handle_clap_error + dispatch fns
  client.rs          # CuClient, CuResponse, send_with_retry, api_error mapping
  config.rs          # Config/AccountEntry TOML, resolve_alias, default paths (directories)
  secrets.rs         # SecretStore trait + KeyringStore + MemoryStore, AccountSecrets
  auth.rs            # minimal token provider (static token from secrets) — no OAuth machinery
  context.rs         # AccountContext + context_for(alias_flag, workspace_flag) — the one wiring seam
  account.rs         # pure helpers (URL building, workspace selection)
  error.rs           # CliError {Api, Usage, Auth, Network} + exit_code() + to_json()
  output.rs          # print_success / print_error (~17 lines)
  commands/          # one file per family; fns take &CuClient, return Result<Value, CliError>, never print
skills/clickup-cli/SKILL.md   # embedded via include_str!; installed by `skill install`
tests/               # per-family wiremock tests + common/mod.rs + cli_smoke.rs + live_smoke.rs

Unit tests for pure logic sit in #[cfg(test)] blocks at the bottom of src files; comments explain why at decision sites (house style).

7. Skill

skills/clickup-cli/SKILL.md, intacct-length (~85 lines): 2-line output contract, "Pick the right command" table, ID-hierarchy primer (workspace → space → folder → list → task; which IDs each family needs), bootstrap block, recipes, exit-code→action table, gotchas (rate limit, hasMore partial data, v3 families needing workspace_id, custom task IDs needing --custom-ids --workspace). Install skips symlinked targets / identical content / missing config dir; update re-execs the new binary for skill install. .gitattributes forces LF so embedded bytes are stable.

8. Tests & CI

  • tests/common/mod.rs: static test token + client_for(&MockServer); command tests call library fns directly and assert returned Values plus request shapes (body_json, query_param, .expect(1) for pagination-stops proofs).
  • Account/config tests: tempfile + MemoryStore + a FailingSecretStore for the write-ordering invariant. cli_smoke.rs (assert_cmd, non-Windows): --help exits 0; unknown alias → exit 2 with "kind":"usage" on stderr.
  • live_smoke.rs: all #[ignore], gated on CLICKUP_LIVE_ALIAS, never in CI.
  • CI: macOS/Windows/Ubuntu cargo test --locked; Ubuntu lint (fmt --check, clippy --all-targets -- -D warnings). Release on v* tags: aarch64/x86_64 macOS + Windows zips via softprops/action-gh-release. No Linux release binary (keyring backend), Linux is CI-only.

9. Dependencies (delta from scaffold)

Scaffold Cargo.toml already matches intacct-cli minus OAuth/XML. Add: self_update (rustls, zip). Remove: webbrowser (unused without an OAuth flow). Keep rpassword (hidden token prompt). No rand/sha2/base64/rcgen/tokio-rustls needed.
