clickup-cli Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Build clickup-cli, a single-binary Rust CLI for AI agents wrapping the ClickUp public API (v2 + the v3 Docs/Chat/attachments/move endpoints), modeled on intacct-cli.

Architecture: Noun-verb command families (task create, time start, …) covering every mainstream API resource, with raw as the escape hatch. All logic lives in the library crate; every command handler takes &CuClient, returns Result<serde_json::Value, CliError>, and never prints; a single dispatcher owns stdout/stderr and exit codes. Personal-token auth only — no OAuth flow, no token refresh, no loopback listener.

Tech Stack: Rust edition 2024, clap 4 (derive), tokio, reqwest (rustls, json, multipart), serde/serde_json, thiserror, keyring 3, directories, toml, url, rpassword, self_update. Dev: wiremock, tempfile, assert_cmd, predicates.

Spec: the approved design at docs/superpowers/specs/2026-08-24-clickup-cli-design.html. Sibling repos ~/projects/creativeplanning/intacct-cli and ~/projects/creativeplanning/netsuite-cli are on disk — when a task says "port", READ the named file and adapt it. Two deliberate deviations from the spec's module list: the minimal auth.rs is folded into context.rs (a static token needs no provider abstraction; tests inject the token via the CuClient constructor), and account.rs's pure helpers (workspace selection) live in commands/account.rs — there is no URL building to share without OAuth.

ClickUp API conventions (every task consumes these)

Verified 2026-08-24 against ClickUp's OpenAPI specs (v2 JSON + v3 YAML) and doc pages. The full endpoint inventory produced during planning is the authority for paths/params quoted in tasks.

  • Auth header: personal tokens are sent RAW — Authorization: pk_… with no Bearer prefix. Tokens never expire; a 401/OAUTH_* error means the token is bad, not stale.
  • Path shapes: v2 is flat (/api/v2/task/{id}, /api/v2/team/{team_id}/space); v3 nests under /api/v3/workspaces/{workspace_id}/…. v2 "team" = Workspace; team_id == workspace_id.
  • Errors: canonical body {"err": "...", "ECODE": "..."}; some (guest/user) endpoints use {"error": "...", "ECODE": "..."} — parse BOTH keys. Message fallback: HTTP status text.
  • Pagination regimes: (a) page-based v2 tasks: ?page=N 0-indexed, 100/page; GET /list/{id}/task and GET /view/{id}/task return {tasks, last_page}; GET /team/{team_Id}/task has NO last_page — stop on a page shorter than 100. (b) comments: newest-first 25/page; next page via start (=last comment's date) + start_id (=its id) together. (c) v3 cursor: ?cursor=&limit=, response carries next_cursor. Everything else returns the full set.
  • Custom task IDs: task-addressed endpoints accept ?custom_task_ids=true&team_id={workspace_id} so {task_id} can be PROJ-123; team_id is REQUIRED alongside custom_task_ids=true. CLI surface: a --custom-id flag on task-addressed verbs.
  • Dates/durations: epoch milliseconds. Task write bodies use markdown_content (not markdown_description); reads add markdown via ?include_markdown_description=true. UpdateTask clears a description with "description": " " (single space).
  • Rate limits: 100 req/min (Free/Unlimited/Business) up to 10k (Enterprise); 429 with X-RateLimit-Reset (epoch seconds). Retry loop honors Retry-After when present, else backoff.
  • Attachments: v2 upload is multipart with file field named attachment; v3 entity attachments use entity_type attachments (a task) or custom_fields (a Files field).

#[derive(Debug, thiserror::Error)]
pub enum CliError {
    #[error("{message}")]
    Api { status: u16, message: String, ecode: Option<String> },
    #[error("{0}")]
    Usage(String),
    #[error("{0}")]
    Auth(String),
    #[error("{0}")]
    Network(String),
}

impl CliError {
    pub fn exit_code(&self) -> u8 {
        match self {
            CliError::Api { .. } => 1,
            CliError::Usage(_) => 2,
            CliError::Auth(_) => 3,
            CliError::Network(_) => 4,
        }
    }

    pub fn to_json(&self) -> Value {
        match self {
            CliError::Api { status, message, ecode } => {
                let mut envelope = json!({"kind": "api", "status": status, "message": message});
                if let Some(code) = ecode {
                    envelope["ecode"] = json!(code);
                }
                envelope
            }
            CliError::Usage(message) => json!({"kind": "usage", "message": message}),
            CliError::Auth(message) => json!({"kind": "auth", "message": message}),
            CliError::Network(message) => json!({"kind": "network", "message": message}),
        }
    }
}

Semantics (port the shape of ~/projects/creativeplanning/intacct-cli/src/client.rs, simplified):

  • Auth header: Authorization: {token} — RAW, no Bearer (personal-token rule; a comment states why). Content-Type: application/json only when a body is present.
  • Retry loop (MAX_ATTEMPTS = 4, BASE_BACKOFF_MILLIS = 500): 429 → sleep Retry-After seconds when the header is present, else exponential backoff, retry; 5xx → backoff, retry; transport error → CliError::Network after retries. 401 → immediate CliError::Auth("ClickUp rejected the token (…message…) — check `clickup-cli account test` or re-run `account add`"), no retry — tokens don't expire, so retrying cannot help. The request builder is a closure re-invoked per attempt (multipart forms are not reusable: build the form inside the closure).
  • Error mapping api_error(status, body_text): parse JSON; message = err key, else error key, else the raw body (truncated to 500 chars), else HTTP status canonical reason; ecode = ECODE key when present. Non-2xx (except 401) → CliError::Api.
  • 2xx with an empty body → CuResponse { status, body: None } (callers synthesize {"status": N} or a domain shape).
